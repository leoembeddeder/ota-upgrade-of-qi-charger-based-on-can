# Flash 空间分配 — QI Wireless Bootloader

> **架构**：Boot + App + 备份区 单 App 升级流（OTA-ARCH-0920，2026-09-20 起）
> A/B 双槽 ping-pong 机制已永久取消。
> **MCU**: AT32F426 (Cortex-M4F, 128KB Flash, 20KB SRAM)
> **Flash 基地址**: `0x08000000` | **总大小**: 128KB (`0x08000000`~`0x0801FFFF`)

## 一、Flash 布局总览

| 区域 | 起始 | 结束 | 大小 | 扇区(4KB) | 说明 |
|---|---|---|---|---|---|
| Bootloader | `0x08000000` | `0x08003FFF` | 16KB (0x4000) | 0~3 | 引导程序：metadata 读取、备份区→App 区搬运、验签、跳转（Keil IROM 实测 `IROM(0x08000000,0x4000)`） |
| App 区（Application） | `0x08004000` | `0x0800FFFF` | 48KB (0xC000) | 4~15 | 应用固件运行区；XATO 头 `@0x08004000`，代码入口 `0x08004100`（Keil IROM1=`0x08004100,0xBF00`） |
| Backup（备份区） | `0x08010000` | `0x0801BFFF` | 48KB (0xC000) | 16~43 | OTA 暂存区：主机经 UDS 写入待升级固件（完整 XATO 镜像），BOOT 校验后搬运至 App 区 |
| Metadata Primary | `0x0801C000` | `0x0801C7FF` | 2KB | 44~45 | OTA 元数据主副本（28B v3 结构） |
| Metadata Backup | `0x0801C800` | `0x0801CFFF` | 2KB | 46~47 | OTA 元数据备副本（先写备后写主，断电可恢复） |
| Device Info | `0x0801D000` | `0x0801DFFF` | 4KB | 48~51 | SN、ECDSA 公钥等设备标识；OTA 擦写永不触碰 |
| NVM Config | `0x0801E000` | `0x0801FFFF` | 8KB | 52~55 | APP NVM 配置区 |

```
0x08000000 ┌──────────────────────────────┐
           │     Bootloader (16KB)        │  0x4000 bytes
0x08004000 ├──────────────────────────────┤
           │     App 区 (48KB)            │  0xC000 bytes
           │  image_header (256B) + app   │  header @0x08004000, entry @0x08004100
0x08010000 ├──────────────────────────────┤
           │     备份区 (48KB)            │  0xC000 bytes（OTA 暂存，出厂 0xFF）
           │  XATO 镜像整体存放           │  BOOT 搬运源
0x0801C000 ├──────────────────────────────┤
           │  Metadata Primary (2KB)      │  ota_metadata_t (28B v3)
0x0801C800 ├──────────────────────────────┤
           │  Metadata Backup  (2KB)      │
0x0801D000 ├──────────────────────────────┤
           │  Device Info (4KB)           │
0x0801E000 ├──────────────────────────────┤
           │  NVM Config (8KB)            │
0x0801FFFF └──────────────────────────────┘
```

地址边界自查：0x08000000+0x4000=0x08004000；0x08004000+0xC000=0x08010000；0x08010000+0xC000=0x0801C000——各区边界相接零重叠。扇区号按 AT32F426 每 4KB 一扇区推算（扇区 N 起址 = `0x08000000 + N×0x1000`）。

## 二、升级流程（单 App 架构）

### 2.1 步骤一：主机侧 — 下载至备份区

主机脚本（zcanpro_ext_ota_auto.py）按序执行：

`10 02` 编程会话 → `27` 安全解锁 → `31` 擦备份区（0x08010000~0x0801BFFF）→ `0x34`（地址门禁：仅接受 0x08010000）→ `0x36` 流式写入 XATO 镜像 → `0x37`。

### 2.2 步骤二：APP 侧 — 校验与提交（ota_download.c）

flush → 长度核对 → verify_backup_image（magic/length/CRC32/ECDSA + Reset 向量必须落在 App 窗口 [0x08004100,0x08010000)）→ commit_backup（metadata：`backup_valid=1` + `backup_crc32`，先备后主双副本落盘）→ 0x77 正响应 → NVIC_SystemReset。

**APP 从不擦写自身所在的 App 区。**

### 2.3 步骤三：BOOT 侧 — 上电搬运（boot_trial.c boot_copy_backup）

上电读 metadata → `backup_valid=1` → 重验备份区镜像 → 擦 App 区 → 字搬运 + 读回复核 → App 区再验签 → **复核通过才清标志**（app_valid=1、backup_valid=0 落盘）→ 跳转 `0x08004100`。

### 2.4 步骤四：断电恢复（幂等）

标志仅在搬运复核通过后清除；擦/搬/复核任一点断电，下次上电整链重跑（备份区为搬运源，不受搬运影响）。copy 失败时 fail_step 记入 metadata reserved_trial[0]、copy_retry_count++，旧 App 若仍可验签则照常启动。

## 三、ota_metadata_t 数据结构（v3 瘦身版，28B，双工程同源，META_VERSION=3）

**Q2 瘦身（2026-09-20）**：按现行升级逻辑删除零读消费字段，布局随版本号解除冻结：

- **删除字段**：reserved_slots / app_crc32 / reserved_trial / reserved2 / padding
- **兼容策略**：v2 及以前 metadata 校验拒绝 → defaults 重建（设备旧数据重建属预期）

| 偏移 | 字段 | 大小 | 说明 |
|---|---|---|---|
| 0x00 | magic | 4B | 0x4F54414D "MATO" |
| 0x04 | version | 4B | 3（v2 及以前拒绝→defaults） |
| 0x08 | app_valid | 1B | App 区镜像有效（M1 诊断帧 b1） |
| 0x09 | backup_valid | 1B | 备份区待搬运标志（升级触发位） |
| 0x0A | copy_fail_step | 1B | 上次搬运失败关卡（原 reserved_trial[0]） |
| 0x0B | last_boot_reason | 1B | 00=POR 01=SW 02=WDG 03=OTA 04=copy失败 |
| 0x0C | backup_crc32 | 4B | 备份区 payload CRC（搬运前比对值） |
| 0x10 | copy_retry_count | 4B | 搬运失败次数（DID 0x2116） |
| 0x14 | ota_state | 1B | 00=idle 01=downloading |
| 0x15 | reserved[3] | 3B | — |
| 0x18 | crc32 | 4B | 以上字段 CRC32（META_CRC32_OFFSET=24） |

合计 0x1C = 28B。

定义源：boot_metadata.h 与 ota_trigger.h 逐字节同构；Python 侧不解析 metadata flash（无偏移耦合）。诊断帧 M1~M4 载荷字段全部保留，抓帧脚本解码无需改动。

## 四、XATO 镜像头（256B，字节偏移锁定）

| 偏移 | 字段 | 大小 | 说明 |
|---|---|---|---|
| 0x00 | magic | 4B | 0x4F544158 "XATO" |
| 0x04 | image_length | 4B | 头之后固件字节数 |
| 0x08 | crc32 | 4B | payload CRC32 |
| 0x0C | signature[64] | 64B | ECDSA P-256 R\|\|S（对 payload） |
| 0x4C | hdr_reserved_ver[16] | 16B | 保留占位（原 version 字段已删除，打包固定填 0x00，偏移不可回收） |
| 0x5C | build_timestamp | 4B | Unix 时间戳 |
| 0x60 | reserved[160] | 160B | 补齐 256B |

版本号不携带于镜像头——唯一真相源 = 固件 `SW_VERSION_STR`（can_protocol.c），DID 0xF195 直读该常量。

## 五、产线烧录

`merge_prod_bin.py`：Bootloader（16KB 补 0xFF）+ App 镜像（XATO，≤48KB）→ `burn bin/prod_image.bin`，烧录基址 `0x08000000`。备份区与 metadata 出厂留 0xFF；首启 BOOT metadata 校验失败→defaults 自愈→直接验签 App 区→置标志→跳转，无需产线预写 metadata。

## 六、诊断（Boot 开机决策链 CAN 标记帧）

ID=0x18FF480D（扩展帧 DLC=8，`[0xA1~0xA4][数据...][0xCC 填充]`）：

- M1 = [app_valid][meta_src][magic][ver][crc]
- M2 = [搬运结果][detail]
- M3 = [pass][fail_step][目标区 0=Backup/1=App]
- M4 = [跳转地址 LE 4B]

抓取工具：`python_tools/zcanpro_boot_diag_capture.py`（通信层 v2）。

## 七、设计约束与注意事项

| # | 约束 | 说明 |
|---|---|---|
| 1 | 地址对齐与擦除粒度 | 各区边界均按 4KB 扇区对齐（见第一节扇区列）；擦除以扇区为单位，UDS `31` 擦除仅作用于备份区（扇区 16~43，0x08010000~0x0801BFFF） |
| 2 | 地址门禁 | `0x34` 仅接受 0x08010000；APP 从不擦写自身所在的 App 区，App 区写入只发生在 BOOT 搬运路径 |
| 3 | ECDSA 验签时机 | 两处必验：① APP 侧 verify_backup_image（commit metadata 之前）；② BOOT 侧搬运完成后对 App 区再验签，复核通过才清标志 |
| 4 | metadata 双副本写入顺序 | 先写备副本（0x0801C800），后写主副本（0x0801C000）；断电时 BOOT 依据副本校验结果选有效副本或 defaults 重建 |
| 5 | 标志清除时机 | backup_valid 仅在搬运+复核通过后与 app_valid=1 同批落盘；擦/搬/复核任一点断电，下次上电整链重跑（幂等） |
| 6 | Device Info 区保护 | 0x0801D000~0x0801DFFF（SN、ECDSA 公钥）OTA 擦写永不触碰 |
| 7 | Reset 向量约束 | App 区镜像 Reset 向量必须落在 [0x08004100, 0x08010000)；打包脚本与 OTA 校验均执行该检查 |
| 8 | 镜像容量上限 | App 区/备份区各 48KB；XATO 镜像（256B 头 + payload）整体 ≤48KB |
| 9 | metadata 版本兼容 | META_VERSION=3；v2 及以前校验拒绝→defaults 重建（预期行为，布局随版本号解除冻结） |
