# Flash 空间分配 — QI Wireless Bootloader

> **架构**：Boot + App + 备份区 单 App 升级流（OTA-ARCH-0920，2026-09-20 起）
> A/B 双槽 ping-pong 机制已永久取消。
> **MCU**: AT32F426 (Cortex-M4F, 128KB Flash, 20KB SRAM)
> **Flash 基地址**: `0x08000000` | **总大小**: 128KB (`0x08000000`~0x0801FFFF`)

## 一、Flash 布局总览

| 区域 | 起始 | 结束 | 大小 | 说明 |
|---|---|---|---|---|
| Bootloader | `0x08000000` | `0x08003FFF` | 16KB (0x4000) | 引导程序：metadata 读取、备份区→App 区搬运、验签、跳转（Keil IROM 实测 `IROM(0x08000000,0x4000)`） |
| Application（App 区） | `0x08004000` | `0x0800FFFF` | 48KB (0xC000) | 应用固件运行区；XATO 头 `@0x08004000`，代码入口 `0x08004100`（Keil IROM1=`0x08004100,0xBF00`） |
| Backup（备份区） | `0x08010000` | `0x0801BFFF` | 48KB (0xC000) | OTA 暂存区：主机经 UDS 写入待升级固件（完整 XATO 镜像），BOOT 校验后搬运至 App 区 |
| Metadata Primary | `0x0801C000` | `0x0801C7FF` | 2KB | OTA 元数据主副本（272B 结构） |
| Metadata Backup | `0x0801C800` | `0x0801CFFF` | 2KB | OTA 元数据备副本（先写备后写主，断电可恢复） |
| Device Info | `0x0801D000` | `0x0801DFFF` | 4KB | SN、ECDSA 公钥等设备标识；OTA 擦写永不触碰 |
| NVM Config | `0x0801E000` | `0x0801FFFF` | 8KB | APP NVM 配置区 |

```
0x08000000 ┌─────────────────────────────┐
           │      Bootloader (16KB)      │  0x4000 bytes
0x08004000 ├─────────────────────────────┤
           │   App 区 (48KB)             │  0xC000 bytes
           │  image_header (256B) + app  │  header @ 0x08004000, entry @ 0x08004100
0x08010000 ├─────────────────────────────┤
           │   备份区 (48KB)             │  0xC000 bytes（OTA 暂存，出厂 0xFF）
           │  XATO 镜像整体存放          │  BOOT 搬运源
0x0801C000 ├─────────────────────────────┤
           │  Metadata Primary (2KB)     │  ota_metadata_t (272B)
0x0801C800 ├─────────────────────────────┤
           │  Metadata Backup  (2KB)     │
0x0801D000 ├─────────────────────────────┤
           │  Device Info (4KB)          │
0x0801E000 ├─────────────────────────────┤
           │  NVM Config (8KB)           │
0x0801FFFF └─────────────────────────────┘
```

地址边界自查：0x08000000+0x4000=0x08004000；0x08004000+0xC000=0x08010000；0x08010000+0xC000=0x0801C000——各区边界相接零重叠。

## 二、升级流程（单 App 架构）

1. **主机侧**（zcanpro_ext_ota_auto.py）：`10 02` 编程会话 → `27` 安全解锁 → `31` 擦备份区（0x08010000~0x0801BFFF）→ `0x34`（地址门禁：仅接受 0x08010000）→ `0x36` 流式写入 XATO 镜像 → `0x37`。
2. **APP 侧**（ota_download.c）：flush → 长度核对 → verify_backup_image（magic/length/CRC32/ECDSA + Reset 向量必须落在 App 窗口 [0x08004100,0x08010000)）→ commit_backup（metadata：`backup_valid=1` + `backup_crc32`，先备后主双副本落盘）→ 0x77 正响应 → NVIC_SystemReset。APP 从不擦写自身所在的 App 区。
3. **BOOT 侧**（boot_trial.c boot_copy_backup）：上电读 metadata → `backup_valid=1` → 重验备份区镜像 → 擦 App 区 → 字搬运 + 读回复核 → App 区再验签 → **复核通过才清标志**（app_valid=1、backup_valid=0 落盘）→ 跳转 `0x08004100`。
4. **断电幂等**：标志仅在搬运复核通过后清除；擦/搬/复核任一点断电，下次上电整链重跑（备份区为搬运源，不受搬运影响）。copy 失败时 fail_step 记入 metadata reserved_trial[0]、copy_retry_count++，旧 App 若仍可验签则照常启动。

## 三、ota_metadata_t 数据结构（272B，双工程同源，META_VERSION=2）

```
Flash 地址 0x0801C000 开始:
magic (4B)                @0x00  ← 0x4F54414D "MATO"
version (4B)              @0x04  ← 2（单 App 格式；v1 数据校验拒绝→defaults）
reserved_slots[2]         @0x08  ← 已废弃（原 active/pending slot）
app_valid (1B)            @0x0A  ← 1=App 区镜像有效
backup_valid (1B)         @0x0B  ← 1=备份区有待搬运固件（搬运标志）
app_crc32 (4B)            @0x0C  ← App 区镜像 CRC32
backup_crc32 (4B)         @0x10  ← 备份区镜像 CRC32（搬运后复核比对值）
reserved_trial[8]         @0x14  ← 已废弃（原 trial 字段）；[0] 兼作 copy fail_step
copy_retry_count (4B)     @0x1C  ← 搬运失败次数（诊断）
last_boot_reason (1B)     @0x20  ← 00=POR 01=SW 02=WDG 03=OTA搬运 04=copy失败
ota_state (1B)            @0x21  ← 00=idle 01=downloading
reserved2[2]              @0x22
padding[232]              @0x24
crc32 (4B)                @0x10C ← 以上字段 CRC32
```

字段定义同步源：`qi_wireless_bootloader/mdk_app/Inc/boot_metadata.h` 与 `qi_wireless_code_app/mdk_app/Inc/ota_trigger.h`（逐字节一致）；Python 侧常量同源：`python_tools/zcanpro_ext_ota_auto.py`、`1.packaging script/verify_image.py`、`merge_prod_bin.py`。

## 四、XATO 镜像头（256B，字节偏移锁定）

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0x00 | magic | 0x4F544158 "XATO" |
| 0x04 | image_length | 头之后固件字节数 |
| 0x08 | crc32 | payload CRC32 |
| 0x0C | signature[64] | ECDSA P-256 R\|\|S（对 payload） |
| 0x4C | hdr_reserved_ver[16] | 保留占位（原 version 字段已删除，打包固定填 0x00，偏移不可回收） |
| 0x5C | build_timestamp | Unix 时间戳 |
| 0x60 | reserved[160] | 补齐 256B |

版本号不携带于镜像头——唯一真相源 = 固件 `SW_VERSION_STR`（can_protocol.c），DID 0xF195 直读该常量。

## 五、产线烧录

`merge_prod_bin.py`：Bootloader（16KB 补 0xFF）+ App 镜像（XATO，≤48KB）→ `burn bin/prod_image.bin`，烧录基址 `0x08000000`。备份区与 metadata 出厂留 0xFF；首启 BOOT metadata 校验失败→defaults 自愈→直接验签 App 区→置标志→跳转，无需产线预写 metadata。

## 六、诊断（Boot 开机决策链 CAN 标记帧）

ID=0x18FF480D（扩展帧 DLC=8，`[0xA1~0xA4][数据...][0xCC 填充]`）：
M1=[app_valid][meta_src][magic][ver][crc]；M2=[搬运结果][detail]；M3=[pass][fail_step][目标区 0=Backup/1=App]；M4=[跳转地址 LE 4B]。抓取工具：`python_tools/zcanpro_boot_diag_capture.py`（通信层 v2）。
