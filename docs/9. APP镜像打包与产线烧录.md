# 9. APP 镜像打包与产线烧录

> **适用**：Keil 编出 Slot A 裸 `.bin` 后加 XATO 头，合并 Boot，产线烧录；SN 由扫码 + CCU UDS 写入
> **脚本**（路径均相对**仓库根**）：
> - `python_tools/1.packaging script/pack_image_slotA_1_1_1.py` — 裸 bin → `app bin/app_slot_a.bin`
> - `python_tools/1.packaging script/merge_prod_bin.py` — Boot + Slot A → `burn bin/prod_image.bin`
> **不需要**：ZCANPRO、`python-can`、`cryptography`（打包/合并用标准库）

下文路径都相对仓库根，不要写死盘符。在仓库根下执行示例命令。

产线正式烧录只烧 **Bootloader + Slot A**（可用合并后的单文件）。Slot B 出厂空着，留给以后 CAN OTA。SN **不**打进这份镜像，上电进 APP 后由 CCU 写入。

---

## 1. Flash 布局（和打包的关系）

```
0x08000000  Bootloader  16KB
0x08004000  Slot A 头 256B     ← pack_image_slotA_1_1_1.py 加上的 XATO 头
0x08004100  Slot A 代码        ← Keil Target → IROM1 从这里开始
0x08010000  Slot B 头 256B     ← 出厂不烧
0x08010100  Slot B 代码
0x0801D000  Device Info 4KB    ← SN 序列号等设备信息，OTA 擦写跳过
```

- Keil 链接地址是 **代码入口** `0x08004100`，产出的裸 `.bin` **不含** 头。
- 打包后的 `.bin`（含 XATO 头） = **256 字节头 + 裸 bin**，必须从槽起始 **`0x08004000`** 烧录。
- 不要把裸 `.bin` 直接烧到 `0x08004100`：没有头则 Bootloader 验签失败，一直停在 Safe Mode（挂起）。

## 2. Keil 生成 Slot A 裸 `.bin`

工程：`qi_wireless_code_slotA/mdk_project/qi_wireless.uvprojx`（唯一 APP 工程）

**只在 Keil Target 里配 IROM/IRAM，不用 scatter 文件。**

Options for Target（魔术棒）→ **Target**：

| 项               | Slot A（唯一工程）            |
| ---------------- | ----------------------------- |
| IROM1 Start      | `0x08004100`                  |
| IROM1 Size       | `0xBF00`（48KB − 256B 头）    |
| IRAM1 Start      | `0x20000000`                  |
| IRAM1 Size       | `0x5000`                      |
| default in IROM1 | 勾选（代码放进 IROM1）        |

Options for Target → **Linker**：

- **勾选** “Use Memory Layout from Target Dialog”（用上面 Target 的 IROM/IRAM 生成链接）
- **不要勾选** Scatter File，也不要再使用已删除的 `scatter\app_slot_*.sct`

当前仓库工程即为 Slot A：IROM `0x08004100` / `0xBF00`，`umfTarg=1`。固件位置无关，写入 B 槽由 OTA 脚本重定位重签，**无需另编 Slot B 镜像**。

Keil 默认只出 `.axf`。在 **Options for Target → User → After Build/Rebuild** 勾选第一项，命令填：

```text
fromelf --bin --output="$L@L.bin" "#L"
```

Rebuild 后得到：

```text
qi_wireless_code_slotA/mdk_project/Objects/qi_wireless.bin
```

文件大小必须 **≤ 48896 字节**（`0xBF00`）。加上头后总长 ≤ 槽大小 `0xC000`（48KB）。

可用 HxD 看裸 `.bin` 开头 8 字节（小端）：

| 偏移 | 含义          | Slot A 大致样子                                        |
| ---- | ------------- | ------------------------------------------------------ |
| 0..3 | 初始 MSP      | `00 xx 00 20`（SRAM `0x2000xxxx`）                 |
| 4..7 | Reset Handler | 落在 `0x080041xx` 一带（最低位为 1 表示 Thumb，正常） |

若 Reset 还在 `0x08000000` 附近，说明 IROM 仍按整片 Flash 链接，不能打包。

## 4. 用打包脚本加头

脚本：`python_tools/1.packaging script/pack_image_slotA_1_1_1.py`。依赖同目录签名函数，**不需要打开 ZCANPRO**。

在仓库根目录：

```text
cd "python_tools/1.packaging script"
python pack_image_slotA_1_1_1.py
```

默认输入/输出（相对仓库根）：

| 参数      | 相对仓库根的路径                                                     |
| --------- | -------------------------------------------------------------------- |
| `--bin` | `qi_wireless_code_slotA/mdk_project/Objects/qi_wireless.bin`         |
| `--key` | `docs/keys/private.pem`                                              |
| `--out` | 默认 `python_tools/app bin/app_slot_a.bin`（按链接槽自动命名）      |

> **镜像头不携带版本号（2026-09-18 起）**：XATO 头 version 区（偏移 0x4C，16 字节）打包时**固定填 `0x00`**，脚本不写、不读、日志不输出版本号。版本号**唯一定义在 APP 固件编译常量 `SW_VERSION_STR`**（`can_protocol.c`），发版只改固件常量 + 文档。**运行版本报告不读镜像头**：DID `0xF195` 应答直接取该编译常量，不读镜像头 / OTA metadata。

```text
python pack_image_slotA_1_1_1.py
```

不带参数即用上述默认值。脚本按镜像 Reset Handler 自动判定链接槽并命名输出（`app_slot_a.bin`）。

成功时打印类似：

```text
固件无头，现场打包 xxxx 字节
打包完成 crc=0x........（版本号不在镜像头，见固件 SW_VERSION_STR）
镜像链接 Slot A, 总长 yyyy
输出: ...\app_slot_a.bin
总长: yyyy  (头 256 + 固件 xxxx)
链接: Slot A  → 产线烧录地址 0x08004000
```

若 **链接不是 Slot A**，说明 Target 的 IROM1 不是 `0x08004100`，不要拿去烧。

常见失败：

| 提示                        | 原因                                                   | 处理                              |
| --------------------------- | ------------------------------------------------------ | --------------------------------- |
| 找不到固件                  | 还没`fromelf` 出 `.bin`，或路径不对                | 按第 2 节生成后再跑               |
| 找不到私钥                  | `docs/keys/private.pem` 不存在                       | 放入与 Bootloader 成对的 PEM      |
| 超过槽大小                  | 裸 bin 大于`0xBF00`                                  | 减小 APP 或核对 Target IROM1 Size |
| Reset Handler 不在 Slot A/B | Target IROM1 Start 不是`0x08004100` / `0x08010100` | 改 Target IROM 后 Rebuild         |

## 5. 头里有什么

`image_header_t` 共 256 字节，与 Bootloader `boot_verify.h` 一致：

| 偏移 | 长度 | 字段            | 说明                           |
| ---- | ---- | --------------- | ------------------------------ |
| 0x00 | 4    | magic           | `0x4F544158`（"XATO"，小端） |
| 0x04 | 4    | image_length    | 裸固件字节数（不含头）         |
| 0x08 | 4    | crc32           | 裸固件 CRC32（IEEE 802.3）     |
| 0x0C | 64   | signature       | ECDSA P-256，`R\|\|S`          |
| 0x4C | 16   | version         | 保留字段，打包固定填 `0x00`，不携带版本号（版本号见固件 `SW_VERSION_STR`） |
| 0x5C | 4    | build_timestamp | 打包时的 Unix 时间             |
| 0x60 | 160  | reserved        | 填 0                           |

签名对象是 **裸固件**（不含头），算法与 Bootloader `uECC` / SHA-256 一致。

## 6. 产线怎么烧

推荐：先合并成一个 bin，从 `0x08000000` 烧一次。SN **不要**打进这份镜像。

| 区域 | 地址 | 产线动作 |
| --- | --- | --- |
| Bootloader | `0x08000000` | 合并镜像前 16 KB |
| Slot A | `0x08004000` | 合并镜像中的 `app_slot_a.bin`（含头）     |
| Device Info | `0x0801D000` | 出厂为擦除态 `0xFF`；**上电后**由 CCU 经 UDS 写入 SN |
| Slot B | `0x08010000` | **不烧** |

上电后 Bootloader 校验 Slot A 通过即跳 APP。Slot B 空着是正常的。Device Info 空着时 `0x22 F18C` 回 NRC `0x31`（尚未赋码）。

### 6.1 合并 Boot + Slot A（`merge_prod_bin.py`）

脚本：`python_tools/1.packaging script/merge_prod_bin.py`（用 `dirname` 推仓库根，不写死盘符）。

```text
cd "python_tools/1.packaging script"
python merge_prod_bin.py
```

默认：

| 参数 | 相对仓库根 |
| --- | --- |
| `--boot` | `qi_wireless_bootloader/mdk_project/Objects/bootloader.bin` |
| `--app` | `python_tools/app bin/app_slot_a.bin` |
| `--out` | `python_tools/burn bin/prod_image.bin` |

布局：偏移 `0x0000` = Boot（不足 16 KB 补 `0xFF`），偏移 `0x4000` = Slot A 打包文件。用 J-Link / AT32 ISP 从 **`0x08000000`** 下载 `burn bin/prod_image.bin`。

`--hex` 可选。Boot 16 KB + 满槽 A 会跨 `0x08010000`，HEX 必须按 64 KB 换 Extended Linear Address（脚本若未分段，产线只用 `.bin`）。

APP 总长必须 ≤ `0xC000`。合并文件**不含** SN。

### 6.2 产线写入 SN（扫码 → CCU → CAN-UDS）

**不经过 J-Link。** 工位流程：

```
扫码枪读产品条码
    → CCU 得到 SN 字符串
    → CAN UDS 写到本模块 Flash Device Info（0x0801D000）
    → 读回校验
```

前提：第 6.1 节镜像已烧、模块已上电并跑在 **APP**（`0x34` 回 `7F 34 11`）。CAN：250 kbps，请求 `0x18DA0D03`，响应 `0x18DA030D`。

| 步 | 谁 | UDS | 说明 |
| --- | --- | --- | --- |
| 1 | 操作员 | — | 扫码枪扫产品条码，CCU 得到 SN（ASCII，≤ 31 字符） |
| 2 | CCU | `10 02` | Programming Session |
| 3 | CCU | `27 01` / `27 02` | SecurityAccess Level 1（ECDSA，私钥在 CCU/产线侧） |
| 4 | CCU | `2E F18C` + SN | 定长 32 字节，不足右补空格 `0x20`，过长截断并失败（NRC `0x31`） |
| 5 | 模块 | — | APP 组 `device_info_t`（magic `DEVI`、version=2、sn、可选 hw_version/日期、CRC32）写入 `0x0801D000` |
| 6 | CCU | `22 F18C` | 读回应与扫码一致（32 字节空格填充） |

正响应：`6E F1 8C`。未进 Programming 或未解锁：NRC `0x22` / `0x33`。

Device Info 布局（v2，512 字节有效，详见文档 2）：

| 偏移 | 长度 | 字段 | 说明 |
|------|------|------|------|
| 0x00 | 4 | magic | `0x44455649` ("DEVI") |
| 0x04 | 4 | version | 格式版本 = 2（v2 新增公钥字段） |
| 0x08 | 4 | crc32 | 覆盖其余字段（与 `boot_crc32` 相同算法） |
| 0x0C | 32 | sn | ASCII，与 DID 载荷对应 |
| 0x2C | 8 | hw_version | 可选；不写则保持 `0xFF` 或编译期默认 |
| 0x34 | 4 | production_date | 可选，Unix 时间戳 |
| 0x38 | 65 | ecdsa_pubkey | SEC1 未压缩 ECDSA P-256 公钥，支持密钥轮换 |
| 0x79 | 1 | pubkey_valid | `0x01`=有效，`0xFF`=未配置 |
| 0x7A | 390 | reserved | `0xFF` |

约束：

- 默认会话 **只读** `0xF18C`，防止售后误改。
- 是否允许产线二次写入（返工改码）由 CCU/工装策略决定；模块侧建议仅在 SN 仍为全 `0xFF` 或显式返工会话下接受覆盖。
- OTA `0x31 FF00` 只擦 A/B 槽，**禁止**擦 `0x0801D000～0x0801DFFF`，升级后 SN 仍在。
- 空片/未赋码：`0x22 F18C` → NRC `0x31`。

> Bootloader 无 UDS（仅选槽+验签+跳转），`0x2E F18C` 写 SN **只能在 APP 中进行**。

## 7. 和 CAN OTA 的关系

| 场景                                | 镜像                          | 说明                                                                                                                                               |
| ----------------------------------- | ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 产线 / 空片双槽无效                 | 本页打出的 `app_slot_a.bin` | 烧到`0x08004000`，或交给 ZCANPRO 下发                                                                                                            |
| APP 已在 Slot A 跑，第一次 CAN 升级 | **无需另编 Slot B**     | 固件只编 Slot A（IROM1=`0x08004100`），OTA 脚本写入 B 槽时自动重定位+重签 |

不能把 Slot A 的包拿去升 Slot B：MCU 写入非活跃槽，Reset Handler 必须落在该槽内，否则 `0x37` 失败。

OTA 脚本已收敛为单一文件：

- `python_tools/zcanpro_ext_ota_auto.py` — APP 内擦非活跃槽 + 下载 + 重定位 + 重签

各脚本中：

- 脚本扫描 `app bin/` 目录自动选择固件，运行时自动加 XATO 头或原样下发。
- 固件只编 Slot A（IROM1=`0x08004100`）；写入 B 槽时脚本自动重定位+重签。

详细 UDS 步骤见 `python_tools/脚本使用说明.md`。

## 8. 步骤清单（Slot A 产线包）

1. Keil Target：IROM1 `0x08004100` / `0xBF00`，勾选 Use Memory Layout from Target Dialog；After Build `fromelf` 出 `qi_wireless.bin`。
2. 确认 `docs/keys/private.pem` 存在且与 Bootloader 公钥成对。
3. 仓库根下 `cd "python_tools/1.packaging script"` 后 `python pack_image_slotA_1_1_1.py`。日志必须是 **链接 Slot A**。
4. 同目录直接 `python merge_prod_bin.py`，得到 `burn bin/prod_image.bin`。
5. 将该文件从 **`0x08000000`** 烧进芯片（ISP / J-Link）。不要单独再烧 SN 二进制。
6. 上电应进入 APP（`0x34` → `7F 34 11`），不要停在 Safe Mode。
7. 扫码枪扫产品条码 → CCU `10 02` + `0x27` 解锁 + `2E F18C` 写 SN → `22 F18C` 核对。
