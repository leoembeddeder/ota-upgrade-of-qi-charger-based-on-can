# python_tools — 脚本使用说明

> **Python**: ZCANPRO 要求 **Python 3.8 32 位**
> **入口**: ZCANPRO → 高级功能 → 扩展脚本
> **总线**: Classical CAN 2.0B，250 kbps，29-bit 扩展帧

---

| 脚本 | 功能 | 位置 |
|------|------|------|
| `pack_image.py` | Slot A 裸 bin → 签名镜像（写入 B 时 OTA 脚本会重定位） | 1.packaging script/ |

## 1. pack_image — 镜像打包

镜像头不携带版本号（0x4C 为保留占位区，原 version 字段声明已从 `image_header_t` 删除，固定填 `0x00`，偏移锁定不可回收）；版本号唯一定义在固件 `SW_VERSION_STR`（`can_protocol.c`），发版只改固件常量 + 文档，打包脚本无版本参数。运行版本（DID 0xF195）读固件编译常量。

```powershell
python "python_tools/1.packaging script/pack_image.py"
```

只编 Slot A（Keil IROM1=`0x08004100`）。不要再打 Slot B 包。

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--bin` | Slot A/B 的 qi_wireless.bin | 裸 APP .bin |
| `--key` | `docs/keys/private.pem` | ECDSA 私钥 |
| `--out` | 自动输出到 `app bin/` | 输出路径 |

## 2. OTA 脚本

下载只在 **APP** 中进行。ZCANPRO 打开 **`zcanpro_ext_ota_auto.py`** 即可：读当前槽，写入对面，镜像若按 A 链接则自动重定位到 B。空片用 `merge_prod_bin.py`。

| 参数 | 值 | 说明 |
|------|-----|------|
| `TRANSFER_BLOCK_DATA` | `128` | 每块字节数 |

| 槽 | 槽基址 | IROM1 Start | IROM1 Size |
|----|--------|-------------|------------|
| Boot | `0x08000000` | `0x08000000` | `0x4000`（16KB） |
| A | `0x08004000` | `0x08004100` | `0xBF00` |
| B | `0x08010000` | `0x08010100` | `0xBF00` |

## 3. Qi IAP 脚本

```powershell
# 在 ZCANPRO 中运行 zcanpro_qi_iap_log1.py 或 zcanpro_qi_iap_log2.py
```

| 参数 | 值 | 说明 |
|------|-----|------|
| `QI_IAP_DATA_LEN` | `22` | 每包最大字节数 |
| `QI_IAP_MAX_RETRIES` | `8` | NRC 0x72 重试次数（启动 + 每包） |
| `QI_IAP_PACKET_DELAY` | `0.2` | 包间延时（秒），给 Qi 芯片写 Flash |
| `QI_IAP_START_DELAY` | `0.5` | `2E 21 30` 成功后再等芯片进入 IAP |
| `STATUS_TIMEOUT` | `120` | 升级超时（秒） |

固件：`python_tools/iap bin/log1.BIN` / `log2.BIN`

log1/log2 除固件名和版本号外完全一致，修改任一脚本后必须同步另一个。

## 4. 功能测试脚本（2.functional test script/）

全部在 ZCANPRO 中运行：

```powershell
python "python_tools/2.functional test script/zcanpro_read_app_version.py"  # 读 0xF195/0xF180/0xF193
python "python_tools/2.functional test script/zcanpro_sn_write.py"          # 写 0xF18C（需 SecurityAccess 解锁）
python "python_tools/2.functional test script/zcanpro_sn_read.py"            # 读 0xF18C（默认会话，无需解锁）
python "python_tools/2.functional test script/zcanpro_sa_lockout_test.py"   # SA 锁定恢复测试（P1：故意错 key+S3 keepalive）
python "python_tools/2.functional test script/zcanpro_qi_read_status.py"    # 读 DID 0x2132，IAP 状态
python "python_tools/2.functional test script/zcanpro_qi_read_version.py"   # 读 DID 0x2133，Qi 芯片版本
python "python_tools/2.functional test script/zcanpro_qi_set_power.py"      # 写 DID 0x210D，功率 500/1000/1500 mW
python "python_tools/2.functional test script/zcanpro_charge_start.py"      # 写 DID 0x2101，使能充电
```

### zcanpro_sn_read.py — SN 读取（写入后验证）

| 项 | 说明 |
|------|------|
| 用途 | 专用读取 SN 码，用于 `zcanpro_sn_write.py` 写入后的验证 |
| DID | 0xF18C（DID_SERIAL_NUMBER），应答 32 字节 ASCII 右补空格（0x20） |
| 前置条件 | 设备处于 APP（Boot safe mode 无法读 SN，脚本 Step 0 自动探测并提示）；CAN 通道 250 kbps 扩展帧已打开；**无需** SecurityAccess 解锁、无需切换会话（固件读门禁=默认会话即可） |
| 输出 | ① SN ASCII（去尾部空格）② hex 全量 32 字节 ③ 有效长度；异常分级提示：未写入（NRC 0x31 / 应答全 0xFF 两种固件判据）、NRC 明细、无应答、全空格警告 |

### zcanpro_sa_lockout_test.py — SA 锁定恢复测试（P1 测试项）

| 项 | 说明 |
|------|------|
| 用途 | **故意错 key 触发 SA 锁定** → S3 keepalive 等待 → 恢复解锁 → 验证会话+安全态在 31s 锁定等待期间是否被 keepalive 保住（d770e86 S3 keepalive 防护实机验证载体） |
| 流程 | Step 0 探测 APP → Step 1 `10 02` 编程会话 → Step 2 故意错 key ×3（假签名=全 0x00，预期 NRC `0x35/0x35/0x36`）→ Step 3 锁定确认（`27 01`→NRC `0x37`）→ Step 4 S3 keepalive 等待 31s（每 3s 发 `3E 80`，逐次打印序号+累计时间+最大间隔）→ Step 5 真 private.pem 恢复解锁（签名后先 `[自检]` public.pem 本地验签，PASS 才发 `27 03×16`→`27 02`，预期 `67 02`）→ Step 6a 解锁确认（`67 01`+32×`0x00`）→ Step 6b 幂等写验证（`2E F1 8C`+相同 SN→预期 `6E F1 8C`） |
| 预期日志要点 | ① Step 2 每次打印 seed(32B)+"故意错误签名（全 0x00）"+NRC ② Step 3 "设备已进入锁定（fail_count≥3，约30s）" ③ Step 4 逐次打印 `keepalive #N（累计 X.Xs）`（约 10-11 次）+ "S3 keepalive 实际发送间隔：最大 X.Xs" ④ Step 5 `  [自检] 签名本地验证 PASS（public.pem 对 SHA-256(seed) 验签通过）`→"ECDSA 真签名完成（自检 PASS）"→"解锁成功：67 02" ⑤ Step 6b "写入成功：6E F1 8C ✓——S3 keepalive 防护有效" ⑥ 结束 `[正面判定] S3 keepalive 防护实机有效…`（keepalive 达标+写步非 0x22 时打印）+ `[判定结论] SA 锁定恢复测试 PASS（keepalive N 次/31s，会话保持有效，写步通过）`；失败判读：Step 6b NRC `0x22`=疑似 S3 会话失效；NRC `0x33` 且 Step 5 未解锁=下游失败（`0x33≠0x22`，会话存活证据=S3 keepalive 有效）；Step 5 `[自检] 签名本地验证 FAIL`=签名数据差分，脚本已拦截发送 `27 03`（设备侧未受影响）⑦ **fail_count 残留场景（2026-09-19）**：复测前未断电重启时 fail_count RAM 残留 → NRC 序列前移（如 `0x35/0x36/0x37` 形态：第 2 次即 0x36、第 3 次 `27 01`→`0x37` 锁定期内）；脚本打印「⚠ 检测到 fail_count 残留（复测前未断电重启）：设备已进入锁定…建议断电重启后重跑以获得标准序列」并**按设计继续后续步骤**（Step 3 锁定确认/Step 4 keepalive/Step 5 恢复解锁对残留场景依然有效）；Step 2 记 FAIL（序列非标准）但结束判定归因为「fail_count 残留形态」，处置指引=断电重启后重跑 |
| 前置条件 | 设备处于 APP（Boot safe mode 脚本 Step 0 自动探测并退出）；CAN 通道 250 kbps 扩展帧已打开；`docs/keys/private.pem`+`docs/keys/public.pem` 存在（脚本自动探测仓库根；public.pem 为签名本地自检用） |
| 注意事项 | ① 错 key 阶段假签名零数据，不消耗设备有效密钥资源（fail_count 是测试目的本身）② 写步仅重写相同 SN 值（幂等，设备状态无变化）③ 锁定态测试后自动清除（30s 到期 fail_count 归零+成功解锁双保险）④ **建议与其他测试错开执行**（避免 fail_count 残留干扰其他 SA 流程）；**复测前置=断电重启**（清零 fail_count RAM 残留；00:03 复测实证：残留 fail_count=1 即导致 NRC 序列前移）⑤ 写步 NRC 判读（2026-09-18 修正）：`0x22`=疑似 S3 会话失效；`0x33` 且 Step 5 未解锁=下游失败（`0x33≠0x22`，会话存活证据=S3 keepalive 有效），仅 `0x22` 才提示疑似 S3 失效 ⑥ Step 5 签名发送前有本地自检（`[自检]` 日志），自检 FAIL 不发送 `27 03` 直接报错——mock/实机都能拦截签名数据差分类缺陷 ⑦ fail_count 残留检测（2026-09-19）：Step 2 检测到 `0x36`/`0x37` 提前出现（锁定类 NRC 早于第 3 次预期位置）时打印残留指引并继续后续步骤（锁定确认→keepalive→恢复解锁→验证），测试结论 Step 2 记 FAIL（序列非标准）但其余步骤照常验证 S3 keepalive 防护与 EC 恢复解锁 |

## 5. 产线工具

### merge_prod_bin.py

最简用法（需先打包好 `app bin/app_slot_a.bin`）：

```powershell
python "python_tools/1.packaging script/merge_prod_bin.py"
```

自定义路径：

```powershell
python "python_tools/1.packaging script/merge_prod_bin.py" --boot <bootloader路径> --app <app镜像路径> --out <输出路径> --hex
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--boot` | bootloader.bin | Bootloader 路径 |
| `--app` | app bin/app_slot_a.bin | 已签名 APP |
| `--out` | burn bin/prod_image.bin | 输出路径 |
| `--hex` | — | 同时生成 .hex |

约束：Bootloader ≤ 28KB，APP ≤ 42KB。

### verify_image.py

```powershell
python "python_tools/1.packaging script/verify_image.py" "python_tools/app bin/app_slot_a.bin"
python "python_tools/1.packaging script/verify_image.py" <image> --key docs/keys/public.pem --slot B
```

依赖：OpenSSL CLI（签名验证用）。

### sign_seed.py

```powershell
python "python_tools/1.packaging script/sign_seed.py" <seed_hex_64chars> --key docs/keys/private.pem
```

seed 为32字节（64个十六进制字符）。
