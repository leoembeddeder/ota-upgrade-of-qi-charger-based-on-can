# Python 脚本使用说明（操作手册）

> 本手册只讲怎么用。原理与取证细节见 `review_reports/` 内各报告。
> 除特别说明外，文中命令均在 `python_tools/` 目录下执行。

## 1. 环境准备

- **上位机**：ZCANPRO + ZCANPRO CAN 设备；运行任何 `zcanpro_*` 脚本前先打开 CAN 通道：**250 kbps，Classical CAN，扩展帧**。
- **Python**：ZCANPRO 扩展脚本需 **Python 3.8 32 位**（ZCANPRO 引擎要求）；`1.packaging script/` 下打包/校验/合并脚本需 Python 3.6+；`sign_seed.py` 额外需要 `pip install ecdsa`。
- **接线确认**：设备上电，CAN_H / CAN_L 接 ZCANPRO；打开通道后先运行任一读脚本（如 `zcanpro_read_app_version.py`）确认总线有应答，再做升级/写入操作。

## 2. OTA 升级操作流程

**第 0 步 · 版本对齐（必做，否则升级被拒）**
固件 `can_protocol.c` 的 `SW_VERSION_STR`（当前 `QC_JYF_FW_1.1.1`）与升级脚本 `zcanpro_ext_ota_auto.py` 的 `EXPECTED_SW_VERSION`（当前 `QC_JYF_FW_1.1.2`）**必须一致**：在 Keil 中把 `SW_VERSION_STR` 改为目标版本 → **Rebuild**（禁 Incremental Build）→ 再打包。两者不一致时脚本拒闪门 fail-closed 拦截升级（找不到版本匹配的载荷）。

**第 1 步 · Keil 编译出裸 bin**
Rebuild `qi_wireless_code_app` 工程，产出 `qi_wireless_code_app/mdk_project/Objects/qi_wireless_code_app.bin`。

**第 2 步 · 打包镜像（必需环节，Keil 裸 bin 不能直传）**

```bash
python "1.packaging script/pack_image.py"
```

产出 `app bin/app_image.bin`。

**第 3 步 · 运行升级主脚本**
ZCANPRO → 高级功能 → 扩展脚本 → 打开 `zcanpro_ext_ota_auto.py` → 运行。
脚本自动执行：选载荷（版本匹配优先）→ 打包/自检 → `10 02` → `27` 安全解锁 → `31` 擦备份区 → `34/36` 写入 `0x08010000` → `37` 验签提交（设备自复位）→ BOOT 搬运 Backup→App。

**第 4 步 · 观察判定闭环输出**
成功：日志输出「判定闭环满足：① 复位后 APP 应答；② 0xF195==预期版本」。
失败：输出差异明细 + 判别矩阵指引，按提示排查。

**第 5 步 · 0xF195 版本核验（复核）**
ZCANPRO 扩展脚本运行 `2.functional test script/zcanpro_read_app_version.py`，确认 0xF195 应答 = 目标版本字符串。

## 3. 各脚本速查

### 3.1 zcanpro_ext_ota_auto.py — OTA 升级主脚本

- **用途**：CAN-UDS OTA 升级全流程自动执行（单 App 架构）。
- **何时用**：固件版本变更后给设备升级。
- **命令**：ZCANPRO → 高级功能 → 扩展脚本 → 打开本文件 → 运行（无命令行参数）。
- **关键参数**：脚本内常量 `EXPECTED_SW_VERSION = "QC_JYF_FW_1.1.2"`，版本不符拒闪；前置 CAN 通道 250 kbps Classical CAN 扩展帧。
- **预期输出**：「判定闭环满足：① 复位后 APP 应答；② 0xF195==预期版本」；FAIL 时输出差异明细 + 判别矩阵指引。

### 3.2 pack_image.py — 打包（必需环节）

- **用途**：Keil 裸 bin → XATO 签名镜像；**裸 bin 不能直接传给设备，必须先打包**。
- **何时用**：每次 Rebuild 之后、OTA 升级或产线合并之前。
- **命令**：

```bash
python "1.packaging script/pack_image.py"
python "1.packaging script/pack_image.py" --bin <裸bin路径> --key <私钥pem> --out-name <输出名>
```

- **关键参数**（argparse）：`--bin` 默认 `qi_wireless_code_app/mdk_project/Objects/qi_wireless_code_app.bin`；`--key` 默认 `docs/keys/private.pem`；`--out-name` 默认 `app_image.bin`，输出到 `python_tools/app bin/`。
- **预期输出**：`output : ...\app bin\app_image.bin`；打包自动执行镜像自检（Reset 窗口 + CRC + 独立仿射验签），FAIL 拒绝产出。

### 3.3 verify_image.py — 镜像校验

- **用途**：校验 XATO 镜像（magic / 长度 / CRC / Reset 窗口 / 可选 ECDSA 签名）。
- **何时用**：打包后、交付或烧录前抽查。
- **命令**：

```bash
python "1.packaging script/verify_image.py" "app bin/app_image.bin"
python "1.packaging script/verify_image.py" "app bin/app_image.bin" --key ../docs/keys/public.pem
```

- **关键参数**（argparse）：位置参数 `image`＝镜像路径（必填）；`--key` 公钥 PEM，**可选**，省略时跳过 ECDSA 检查（此时 PASS ≠ 签名已验；pack 打包时已无条件自检验签）。
- **预期输出**：`RESULT: PASS` 方可交付。

### 3.4 merge_prod_bin.py — 产线合并 bin

- **用途**：`bootloader.bin` + `app_image.bin` 合并为单个产线烧录 bin。
- **何时用**：产线烧录、整片固件更新。
- **命令**：

```bash
python "1.packaging script/merge_prod_bin.py"
python "1.packaging script/merge_prod_bin.py" --boot <bootloader路径> --app <镜像路径> --out <输出路径> --hex
```

- **关键参数**（argparse）：`--boot` 默认 `qi_wireless_bootloader/mdk_project/Objects/bootloader.bin`；`--app` 默认 `app bin/app_image.bin`；`--out` 默认 `burn bin/prod_image.bin`；`--hex` 附带产出 Intel HEX。
- **预期输出**：`burn bin/prod_image.bin`；布局 Boot(16KB)+App 镜像，备份区/metadata 出厂留空（Boot 首启自愈）；烧录基址 `0x08000000`。

### 3.5 sign_seed.py — 0x27 SA seed 签名

- **用途**：对 MCU 返回的 32 字节 seed 计算 ECDSA P-256 签名，输出可直接手动发送的 CAN 帧 hex。
- **何时用**：手动测试 SecurityAccess（0x27）解锁时。
- **命令**：

```bash
python "1.packaging script/sign_seed.py" <seed_hex>
python "1.packaging script/sign_seed.py" <seed_hex> --key docs/keys/private.pem
```

- **关键参数**（argparse）：位置参数 `seed`＝64 个 hex 字符（32 字节，来自 `67 01` 应答）；`--key` 默认 `docs/keys/private.pem`。
- **预期输出**：`27 03` 分片帧（4 字节签名/帧）与 `27 02` 帧的 hex 列表，可直接在 ZCANPRO 手动发送。

### 3.6 zcanpro_boot_diag_capture.py — Boot 诊断抓帧（M1~M4）

- **用途**：复位设备并抓取 Boot 开机决策链诊断标记帧（CAN ID `0x18FF480D`），逐帧解码。
- **何时用**：排查开机 / OTA 搬运异常；前提是 Boot 已烧录诊断标记版构建。
- **命令**：ZCANPRO → 扩展脚本 → 打开本文件 → 运行；脚本内 `CAPTURE_WINDOW_S = 30.0`（复位后捕获窗口秒数）。
- **帧含义**：
  - **M1 (0xA1)**：metadata 读取现场 `[app_valid][meta_src][magic][ver][crc]`
  - **M2 (0xA2)**：搬运结果帧 `[info][ret]` — `ret=1`=提交成功（Backup→App 已提交）；`ret=0xFF`=失败（info=fail_step，flag 保留下轮开机重试）；`ret=0, info=0`=搬运序列开始（有待搬运镜像）；`ret=0, info=0xFF`=无待搬运固件（常规开机无 OTA 待搬运时发射）
  - **M3 (0xA3)**：验签现场 `[pass][fail_step][target]` — target `0`=Backup / `1`=App
  - **M4 (0xA4)**：跳转目标 `[地址 LE 4B]` — `0x08004100`=App 区
- **预期输出**：逐帧人话解码 + 决策链摘要 + 总线活动统计。

### 3.7 zcanpro_qi_iap_log1.py / zcanpro_qi_iap_log2.py — Qi 芯片 IAP 日志

- **用途**：通过 CAN-UDS 经 MCU UART 转发，升级 Qi 无线充芯片固件。
- **何时用**：按目标 Qi 芯片版本选脚本：`zcanpro_qi_iap_log1.py`→`iap bin/log1.BIN`（Qi V1.1）；`zcanpro_qi_iap_log2.py`→`iap bin/log2.BIN`（Qi V1.2）；**两者与固件严禁混用**。
- **命令**：ZCANPRO → 扩展脚本 → 打开对应文件 → 运行；固件目录固定 `python_tools/iap bin/`。
- **流程**：读 `0x2133` Qi 版本 → 编程会话 + 安全解锁 → `0x2130` 启动 IAP → `0x2131` 分包发送（22 字节/包）→ `0x2132` 轮询状态。
- **预期输出**：`0x2132` 状态 `0x02`=成功、progress 100%。

### 3.8 功能测试脚本（2.functional test script/）

以下脚本统一用法：ZCANPRO → 高级功能 → 扩展脚本 → 打开对应文件 → 运行；前置 CAN 通道 250 kbps Classical CAN 扩展帧。

| 脚本 | 用途（一行） | 命令 / 关键参数 |
|---|---|---|
| `zcanpro_read_app_version.py` | 读 APP 侧版本 DID 0xF195 / 0xF180 / 0xF193 | ZCANPRO 打开运行；脚本内期望值 0xF195=`QC_JYF_FW_1.1.1`、0xF180=`QC_JYF_BL_1.0.0`、0xF193=`QC_JYF_HW_1.1.5`（固件版本变更后需同步脚本期望值） |
| `zcanpro_sn_write.py` | 写入 SN 序列号（`0x2E F1 8C`，需编程会话+安全解锁） | ZCANPRO 打开运行；SN 在脚本内 `SN_CODE` 修改（默认 `LSCH42JY012606020001`） |
| `zcanpro_sn_read.py` | 读取 SN（`22 F18C`，默认会话即可，无需解锁） | ZCANPRO 打开运行；NRC `0x31` 或应答 32 字节全 `0xFF` = 未写入 |
| `zcanpro_charge_start.py` | 启动 Qi 无线充电（解锁→设功率→使能→轮询至 CHARGING） | ZCANPRO 打开运行；脚本内 `POWER_LEVEL = 0x03`（默认 15W） |
| `zcanpro_charge_stop.py` | 停止充电（`0x2E 21 01 00`，与 charge_start 配对） | ZCANPRO 打开运行；判据=充电状态读回非 `0x04` |
| `zcanpro_qi_set_power.py` | 设置 Qi 充电功率（`0x2E 21 0D`，uint16 LE，单位 mW） | ZCANPRO 打开运行；脚本内 `POWER_MW = 1500`（可选 500/1000/1500）；需扩展会话+安全解锁 |
| `zcanpro_qi_read_status.py` | 读 Qi IAP 升级状态 DID `0x2132`（state/progress/版本/已发/总长） | ZCANPRO 打开运行；任意会话可读 |
| `zcanpro_qi_read_version.py` | 读 Qi 芯片固件版本 DID `0x2133`（uint16 LE，未上报=`0x0000`） | ZCANPRO 打开运行；任意会话可读 |
| `zcanpro_sa_lockout_test.py` | SA 锁定恢复测试：故意错 key×3 触发锁定→等待→真签名解锁 | ZCANPRO 打开运行；脚本内 `WRONG_KEY_ATTEMPTS = 3`、`SN_CODE` 可调 |

## 4. DID 判读速查表

| DID | 含义 |
|---|---|
| `0xF195` | 运行固件版本（32 字节 ASCII，来源=固件 `SW_VERSION_STR`）——**OTA 升级判定闭环依据** |
| `0x2113` | 运行区标识：单 App 架构恒 `0x00`=App 区运行，仅信息展示 |
| `0x2114` | OTA 目标标记：`0x02`=备份区有待搬运镜像（backup_valid 有效），`0xFE`=无待搬运镜像 |
| `0x2115` | last_boot_reason：`0x00`=上电、`0x01`=软件复位、`0x02`=看门狗、`0x03`=OTA 搬运、`0x04`=搬运失败 |
| `0x2116` | 搬运重试计数（copy_retry_count 低 8 位） |

## 5. 常见问题

1. **升级被拒 / 找不到版本匹配载荷** = 固件 `SW_VERSION_STR` 与脚本 `EXPECTED_SW_VERSION` 未对齐 → Keil 中改版本号 → Rebuild（禁 Incremental）→ 重新 `pack_image.py` 打包后再升级。
2. **verify_image 输出 PASS 但没带 `--key`** = 签名未验证，属正常：`--key` 是可选项，且 `pack_image.py` 打包时已无条件自检验签（FAIL 拒绝产出），日常流程省略 `--key` 即可。
3. **升级中途断电** = 设备重新上电后自动整链重试（先验后擦→搬运→复核→清标志，幂等设计），**无需人工干预**，等下一次判定闭环输出即可。
4. **v2 旧 metadata 设备首次升级后 metadata 被重建** = 属预期行为：旧版本 metadata 校验不符→默认值重建，历史字段归零，不影响升级结果判定。
